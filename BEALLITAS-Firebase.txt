MI EZ AZ APP?
  A Slotli egy időpontfoglaló + számlázó. A tulaj bejelentkezik, és a
  foglalásait/számláit kezeli a felhőben (Firestore: vaults/{uid}).
  PLUSZ: generál egy BEÁGYAZHATÓ foglaló-widgetet idegen weboldalba.
  A látogató foglal, a foglalás a Firestore-ba kerül, és ÉLŐBEN megjelenik
  a Slotli-fiókodban. A foglalt idősávok is a felhőben vannak, így
  KÉT ember nem foglalhatja ugyanazt (ütközésvédelem).

  Három Firebase-szolgáltatás kell:
    - Authentication → a tulaj bejelentkezése (e-mail/jelszó).
    - Firestore     → a tulaj adata + a beérkező foglalások + a foglalt
                      idősávok + a foglaló-konfig.
    - Hosting       → a Slotli weboldal kiszolgálása (HTTPS-sel).

5) FIRESTORE SZABÁLYOK — MAGYARÁZAT (firestore.rules)
----------------------------------------------------------------------
Négy rész:

  a) A tulaj privát adata:
       match /vaults/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }

  b) Nyilvános foglaló-konfiguráció (a widget ebből tölti a szolgáltatásokat/
     nyitvatartást):
       match /booking_configs/{uid} {
         allow read: if true;                          // bárki OLVASHATJA
         allow write: if request.auth != null && request.auth.uid == uid;
       }

  c) Foglalt idősávok (ütközésvédelem — a dokumentum azonosítója maga a
     sáv, és csak akkor hozható létre, ha még nem létezik):
       match /busy/{uid}/slots/{slotKey} {
         allow read: if true;                          // a widget látja, mi foglalt
         allow create: if !exists(.../slots/$(slotKey));  // csak ha még szabad
         allow update, delete: if request.auth != null && request.auth.uid == uid;
       }
     → két egyidejű foglalás ugyanarra a sávra: az első létrehozza, a
       második "már létezik" miatt elbukik. Így nincs dupla foglalás.

  d) Beérkező foglalások inboxa:
       match /inbox/{uid}/items/{docId} {
         allow create: if request.resource.data.size() < 40;   // bárki LÉTREHOZHAT
         allow read, delete: if request.auth != null && request.auth.uid == uid;
       }

A "firebase deploy" a szabályt automatikusan felteszi.

7) DEPLOY UTÁN — FONTOS (a beágyazott widgethez)
----------------------------------------------------------------------
1. Nyisd meg az élő Slotlit (slotli-202608.web.app) → REGISZTRÁLJ /
   jelentkezz be → a "Foglaló / weboldal" fülön állítsd be a
   szolgáltatásokat, nyitvatartást, sávhosszt és MENTS. Ekkor kerül fel a
   foglaló-konfig a Firestore-ba (booking_configs), hogy a widget lássa.
2. Másold ki a "Foglaló" fülön a GENERÁLT beágyazó kódot, és tedd az
   idegen weboldalba. (A foglalás a Firestore inboxba kerül, a foglalt
   sávok a busy-ba — a "Foglalások" fülön élőben látod.)
3. Tesztelés: foglalj egy próbaidőpontot → nézd meg a Foglalásoknál, és
   próbáld ugyanazt a sávot mégegyszer → "épp lefoglalták" üzenetet kell
   kapnod (ütközésvédelem).

9) (AJÁNLOTT) APP CHECK — bot-védelem a nyilvános íráshoz
----------------------------------------------------------------------
A foglaló-widget NYILVÁNOSAN ír (inbox + foglalt sávok), ezért botok
spammelhetik / lefoglalhatják a sávokat. Ez ellen az App Check (reCAPTCHA
v3) véd.
FIGYELEM: a reCAPTCHA domain-hez kötött — a widgetet csak a felvett
domaineken engedi. Ha "bárhová" ágyazod, ez korlátozó; amíg kevés, ismert
oldalra teszed, praktikus.
  Console → Build → App Check → a Web app → Register → reCAPTCHA v3
  → a site key a kódba, a secret a Firebase-be. Először "Unenforced"!
